# omni-llm-mcp reference

A zero-dependency **MCP stdio server** that wraps the Google **Antigravity CLI (`agy`)**, **OpenAI (ChatGPT/Codex)**, **xAI Grok (Grok Build CLI)**, **Claude Code CLI**, **Pi coding-agent CLI**, **Cursor Agent CLI**, and **Local LLM (Ollama/LM Studio)** as MCP tools — so any project can call different models flexibly from inside Claude Code.

## Why it is designed this way

- **Zero dependencies, zero venv**: Pure stdlib. The system `python3` (≥3.7) is enough to run it; any project can take it with **zero install**. No `pip install openai` or `litellm` is required.
- **Ride your login; no API key (for agy)**: `agy -p` uses OAuth (the Google account you are already signed in with). No metered Gemini API is required.
- **Local and OpenAI support**: Pass API keys through environment variables (`OPENAI_API_KEY`), or call `ollama/llama3` directly. This MCP handles network requests with the native `urllib`.
- **Multi-account profiles (Account Profile)**: `account_profile` must select a separate login; otherwise it LOUD-rejects. Codex uses `CODEX_HOME_<NAME>`, Claude uses `CLAUDE_CONFIG_DIR_<NAME>`, and Grok uses `GROK_HOME_<NAME>`, each pointing at an existing independent directory. There is no cap of two accounts. Cursor keeps `OMNI_LLM_CURSOR_CONFIG_DIR_<NAME>` / `CURSOR_API_KEY_<NAME>`. agy / openai keep their original mechanism. Non-default profiles for pi / ollama / lmstudio still return `unsupported_profile`. When the ring is not enabled, default keeps the original environment.
- **One shared machine, policy owned per project**: This server is a clean **"text in → text out"** pipe and does not inspect content. Policy for "what may be sent, and how output is used" stays in each project's own CLAUDE.md.

## Account profile listing and checks

`omni profiles` lists the account profiles on each road (claude / codex / grok / cursor), including identity and status. `--json` / `--road` / `--name` attach only to the `list` / `check` / `add` subcommands (attaching them to the `profiles` parent command is overwritten by subparser defaults). A tty prints a table; `--json` or a non-tty prints JSON. When cursor has no key/config set, the default state is `unconfigured` (a named status; it does not enter problems). `omni profiles check [--live] [--road R] [--name N] [--strict-quota]` checks shape, identity, quota (codex only), and an optional live session, in that order. If any cell has a problem, the process exits non-zero. Codex cooldown (quota reached / used≥95) is shown only under COOLDOWN and does not fail `check`; `--live` still runs. Failure to read quota is always a problem. Only `--strict-quota` treats cooldown as failure (exit 2). `omni profiles add <road> <name> [--exec] [--persist]` creates `~/.<road>-<name>` (mode 0700; an existing empty directory of the same name is reused, and is not treated as already exists; cursor supports only `CURSOR_API_KEY_<NAME>` and does not create a directory), and prints the vendor login command (`CLAUDE_CONFIG_DIR=<dir> claude auth login` / `CODEX_HOME=<dir> codex login` / `GROK_HOME=<dir> grok login`). `--exec` runs that command in the foreground only on a tty, then runs a `--live` check. Without a tty it LOUD-rejects. A non-zero login exit code is reported as `login_failed` (detail includes rc and the directory). If the directory is still empty it is deleted so the attempt can be retried; otherwise it is left in place and the detail explains why. `--persist` appends `export <VAR>=<dir>` to `~/.config/omni-llm/profiles.env` (directory 0700, file 0600, deduplicated by variable name) and prints a JSON snippet that can be pasted into the MCP server `env`. It never modifies any harness config file. For cursor, `--persist` is a LOUD `unsupported_persist` (the snippet is still printed). A non-empty name that already exists in env or discovery is rejected. Scanning `~/.claude-<name>` / `~/.codex-<name>` / `~/.grok-<name>` is opt-in: it turns on only when `OMNI_LLM_PROFILE_DISCOVERY=1`. On failure it turns off (symlinks, the same realpath as another profile or the default root, a uid that is not this process, or group/other writability are all rejected). This set of commands is not an MCP tool.

Scheduled probe: `omni profiles schedule --print` prints a launchd plist (label `com.omni-llm.profiles-probe`, which by default runs `omni health --probe --all-profiles --json --quiet` every 15 minutes, with stdout written to `~/.local/state/omni-llm/logs/profiles-probe.log`). `--install` is what writes it into `~/Library/LaunchAgents` and runs `launchctl bootstrap`; it is not installed by default. `--uninstall` unloads and deletes the file; if it is not installed, the result is LOUD. On failure the result is LOUD, and detail carries the launchctl rc. `--print` does not write a file and does not call launchctl.

Install from the main checkout (ProgramArguments pins the `omni_cli.py` path at that moment). After the checkout moves, run `--install --force` again. `--install` from a linked worktree (the directory contains a `.git` file, not a directory) LOUD-reports `worktree_checkout` unless `--force` is added.

For registration, status, and message forwarding of existing work sessions in the same repo, see [Session Router](session-router.md).

## Tools

| Tool | Purpose | Returns |
|---|---|---|
| `llm_generate(prompt, model?, account_profile?, effort?, ...)` | General Q&A / multimodal analysis | `{ok, text, model, usage?}` or `{ok:false, reason, detail}` |
| `llm_big_context(instruction, text\|source_path, effort?, ...)` | Large-context digestion (inline or a local file) | Same as above; a path failure includes `error_code` |
| `list_models()` | List agy models plus the static backends routing map and seat health | `{ok, models, default, backends, health}` or `{ok:false, reason, detail, backends, health}` |
| `llm_image(prompt, backend?, source_image?, ...)` | Image generation / editing (cli or rest) | `{ok, model, n, images:[{path\|url}]}` or a LOUD `{ok:false, reason}` |

- **Model names**: 
  - The default uses an `agy` model (for example `Gemini 3.8 Flash (High)`).
  - Passing `gpt-4o` automatically uses OpenAI (HTTP API, `OPENAI_API_KEY`).
  - Passing a name that starts with `codex/`, such as `codex/gpt-5.6-sol`, automatically uses the **OpenAI Codex CLI** (rides a ChatGPT / Codex subscription, zero API key; see the Codex section below). The `read-only` sandbox **is not the same as sealed** — codex can read **any file** on this machine, so send only public data.
  - Passing a name that starts with `claude/`, such as `claude/opus`, automatically uses the **Claude Code CLI** (rides a Max subscription, zero API key; `-p` is a single shot, `--strict-mcp-config` loads no MCP, and write/exec tools are disabled; `OMNI_LLM_DEPTH` is the recursion guard that breaks the claude→omni→claude chain).
  - Passing a name that starts with `pi/`, such as `pi/anthropic/claude-sonnet-5`, automatically uses the **Pi coding-agent CLI** (rides the local `pi` login / `~/.pi/agent/auth.json`, zero API key; consult uses `-p --mode json --no-tools --no-session`, and the agent opens tools; `OMNI_LLM_DEPTH` is the recursion guard that breaks the pi→omni→pi chain). Grok still defaults to the **Grok Build CLI** (`grok-4.6`); dispatching Grok through pi requires the explicit name `pi/xai/grok-4.6`.
  - Passing a name that starts with `cursor/`, such as `cursor/fable`, `cursor/sol`, `cursor/claude-fable-5`, or `cursor/gpt-5.6-sol`, automatically uses the **Cursor Agent CLI** (`cursor-agent`, riding a Cursor subscription or `CURSOR_API_KEY`; **do not** call the binary named `agent`, which is the Grok Build CLI). Short names map as `fable`→`claude-fable-5-1` and `sol`→`gpt-5.6-sol`; every other name is passed through unchanged as `--model`. consult: `-p --mode ask --output-format json --trust --sandbox enabled`, with an empty temp workspace; on Darwin, after the host fence wraps the process, the inner `--sandbox` is changed to `disabled` plus a per-run temp `CURSOR_CONFIG_DIR`; `files=` is a LOUD refusal; `effort` is **folded into the model slug** by this channel (cursor-agent has no effort flag); `OMNI_LLM_DEPTH` is the recursion guard. On a successful envelope, `model` is `cursor/<slug after the alias>` (for example `cursor/sol` → `cursor/gpt-5.6-sol-medium`), and a second call still goes through cursor. Cursor is the CLI path that reaches the model, and it is a new family. Fable on Cursor may require data retention to be enabled in the Dashboard. The agent lane is already wired: `omni agent -m cursor/<model>` uses the same `-p`; see the agent-lane table and the Cursor section below for details.
  - Passing `ollama/llama3` automatically uses the local `http://localhost:11434`.
  - Passing a name that starts with `grok`, such as `grok-4.5`, automatically uses the **Grok Build CLI** (rides a SuperGrok / X Premium subscription, zero API key; see the Grok section below).
  - **Comma-separated = fallback chain (opt-in)**: for example `"Gemini 3.5 Flash,gpt-4o,ollama/llama3"`, tried from left to right until one succeeds. A single model means **no fallback**; whether it is enabled is decided by the caller. When every seat fails, the final `{ok:false}` includes `tried`, recording which models were attempted.
- **agy CLI prompt delivery**: requests of 32 KiB or less keep the original `-p` text; larger requests first write the full UTF-8 bytes to an input file in a private temp directory (exclusive, symlink following forbidden, `0600` while writing and `0400` after completion), then create a read-only host fence in the same workdir. `-p` passes only the file path, the length, the SHA-256, and instructions to page through to EOF with a read-only tool and then handle the original request, so a large body is kept out of a CLI argument that might be truncated. This is still one model request: it is not split into chunks and the model is not changed; the input file is cleaned up after success, failure, or cancellation. The file-path route keeps the composed prompt's 12 MiB local limit (including `files=` appended text); over the limit it returns `payload_too_large` explicitly; the original inline argv guard remains 600 KiB. 32 KiB is a routing threshold and 12 MiB is a local guard; neither is a provider context guarantee. This path needs a read-only file tool and does not claim to be tool-free; actually receiving the full payload still has to be verified with evidence such as source head and tail or a receipt.
- **`files`**: semantics split by backend — `agy`: paths/URLs are appended into the prompt text and parsed by agy itself (unchanged). `codex/<model>`: every item must be a **local file that already exists**, passed one by one to `codex exec` as the native vision argument `-i <path>` (codex reads the file itself; the server does not; URLs are not supported). `grok*`: every item must be a local file that already exists under the **`OMNI_LLM_SOURCE_ROOTS`** allowlist, and its extension must fall in one of **two allowlists** — **images** (png/jpg/jpeg/gif/webp) or **text** (txt/log/md/py/json/yaml/yml/toml/csv); the server reads the file (TOCTOU-safe), then base64-encodes images into an `image` block and strict-decodes text as UTF-8 into a `resource` block (`{"type":"resource","resource":{uri,mimeType,text}}`, content inline), and sends them together with the prompt as a single `--prompt-json` ACP payload. Text attachments have a **stricter inline limit**: 256 KiB per file and 512 KiB in total (both below the 600 KiB argv payload limit, so both limits actually stop the request); over the limit it is a LOUD `reason: files_too_large`, and it is **never silently truncated**. A non-UTF-8 text attachment is a LOUD `unsupported_files` (with `error_code: source_invalid_utf8`). Binary files outside the two allowlists (pdf and the like) stay a LOUD `unsupported_files` — there is currently no ACP block type, verified in practice, that can carry them. **`OMNI_LLM_SOURCE_ROOTS` is a PUBLIC-only contract**: a text attachment sends the file contents under those roots **verbatim** off the machine (it is no longer only image bytes), so roots may point only at directories that are known to be public — de-identification must happen in the contents of the roots themselves; the server will not, and cannot, filter on your behalf. Every other backend (OpenAI / Ollama / LM Studio / Claude / Pi / Cursor) **still LOUD-refuses** (`reason: unsupported_files`) and does not silently drop the files.
- **`effort`**: optional. It applies to `agy/`, `grok*`, `claude/*`, `codex/*`, `pi/*`, and `cursor/*`. Shared legal values are `low` / `medium` / `high` / `xhigh`; agy and claude also accept `max`, and codex and pi also accept `minimal` / `max`. pi maps to `--thinking`, and the public tokens do not accept `off` / `none`. grok 1.0.4 accepts `low` / `medium` / `high` / `xhigh`. agy confirms `--effort` and `low` / `medium` / `high` / `xhigh` / `max` from the installed CLI's `--help`; when effort is specified it always goes through the CLI, and when it is omitted the original SDK/CLI choice is kept. OpenAI HTTP, ollama, and lmstudio LOUD-refuse effort. cursor has no effort flag, so the token is folded into the model slug (see the Cursor section for details). Each seat in a fallback chain validates on its own: if a previous grok seat fails and the next seat is ollama, ollama still refuses because of effort. A trailing `@<token>` on the model name is the same shorthand on agy, grok, claude, codex, pi, and cursor; the narrow exception is only `agy-opus-<version>@med`, where `med` is normalized to `medium`; any other illegal token, or specifying both `@` and `effort=`, always returns a LOUD `unsupported_effort`.
- **Family short names**: a bare name `sol` / `fable` (case-insensitive; it must be the **entire** name after splitting off `@effort`) expands into an ordered set of `(road, model, profile)` seats, dispatched by the existing fallback loop in table priority order, and it never falls through to `agy` or to a road outside the table. `cursor/sol` is not a family; it remains cursor's own alias.
  - Table: `sol` → `codex/gpt-5.6-sol` then `cursor/gpt-5.6-sol`; `fable` → `claude/claude-fable-5-1` then `cursor/claude-fable-5-1`.
  - The environment override `OMNI_LLM_FAMILY_<NAME>` (NAME in uppercase) is a comma-separated list of `road[:profile]`. The model-id always comes from the static table; env cannot change it. An unknown road, a duplicate road, an empty list, or a format error makes the whole request a LOUD `family_config` (detail names the variable), and it is a "yet another failed seat".
  - Profile precedence: a non-default `account_profile` at the call layer applies to **every** seat and overrides `:profile` in env; when the call layer is default (`None` / `""` / `"default"`), each env entry's own `:profile` applies only to that seat (omitted means default).
  - `require_read_wall` (tool argument / `omni gen|big --require-read-wall` / when omitted, look at `OMNI_LLM_REQUIRE_READ_WALL=1`): a seat whose `backends_snapshot()[road].read_wall` is false is marked `ineligible` (`read_wall_required`). Codex and Claude are marked true only when the host read-wall canary passes, and each still verifies the actual provider policy before its consult spawn. If every family seat is ineligible → `no_eligible_seat`, and `tried` keeps every seat; a single explicit model that is ineligible is a direct LOUD `read_wall_required` (it is not wrapped in `no_eligible_seat`).
  - When there is no dispatchable seat (all are `unsupported_effort` / `unsupported_profile` / `read_wall_required`) → `{ok:false, reason:no_eligible_seat, tried}`. A seat that is cooling down is still dispatched after every healthy seat has failed.
  - A successful envelope adds one `seat`: `{family, provider, model, account_profile}`. `family` is `null` on an explicit model; `model` is the road slug that was actually dispatched (for example `cursor/gpt-5.6-sol`), while the top-level `model` on the envelope is still the value that road returned today. `tried` carries `{model, account_profile, reason}` for a family seat.
  - **Profile ring**: `OMNI_LLM_PROFILES_<ROAD>` is a comma list of any length; ROAD supports `CODEX` / `CLAUDE` / `GROK` / `CURSOR`. Codex / Claude / Grok share one account selector across consult, synchronous exec, and detached jobs, and walk the list in order, skipping a missing directory, a duplicate canonical home, and a cooling-down account. Codex also skips an exhausted or unknown quota; Claude / Grok have no numeric quota oracle, and a managed reply is marked `quota_verified: false`. A failure after a tool has run stops that piece of work, and the account changes only on a later new dispatch; Codex / Claude / Grok never re-run the same request across accounts — a Codex startup quota / auth failure also returns only a failure envelope and cools that account down, and the next request selects the next account. resume is pinned to the original profile and canonical home, and a changed mapping is refused. A named `account_profile` / `--profile` pins the specified account; with no ring, the original call style is kept. A duplicate name, an empty segment, an unknown road, or `auto,b` returns `profile_config`; `auto` requires `OMNI_LLM_PROFILE_DISCOVERY=1`. Codex / Claude / Grok exhaustion returns `account_exhausted`, and it returns only validated labels and the named reason. Cursor keeps the existing consult expansion and `no_eligible_seat` semantics. See [Account failover design](account-failover.md).

  - **Automatic account selection (any number of accounts)**: for example `CODEX_HOME_A` / `B` / `C` together with `OMNI_LLM_PROFILES_CODEX=a,b,c`; for Claude, switch to `CLAUDE_CONFIG_DIR_<LABEL>` and `OMNI_LLM_PROFILES_CLAUDE`, and for Grok, switch to `GROK_HOME_<LABEL>` and `OMNI_LLM_PROFILES_GROK`. Each directory is logged in on its own and does not share auth, config, or session; the child process clears sibling and inherited vendor API-key/token/endpoint overrides. `omni profiles add <road> <label> --exec --persist` can prepare the directory and start login; choosing the account in the browser and granting authorization are still done by the user. `OMNI_LLM_QUOTA_PROBE=0` disables only the Codex quota RPC and allows unverified candidates; cooling-down accounts are still skipped.
  - **Claude API key fallback account (off by default)**: `OMNI_LLM_API_PROFILES_CLAUDE=<label>` declares a label inside the ring as an API key account, and `OMNI_LLM_API_FALLBACK_CLAUDE=1` is what allows it to be selected automatically, and only when every preceding subscription account was skipped because it is cooling down; an explicitly specified account (or resume) must also set `OMNI_LLM_API_FALLBACK_CLAUDE=1`, otherwise it returns `api_disabled` before the child process starts; the last step before spawning the child checks once more, and if a preceding subscription account has already recovered it returns `api_not_permitted` and does not start the API child. `--max-budget-usd` is only the vendor CLI's cooperative cap, and it is a safety boundary; the spend boundary is the Console workspace spend cap plus not buying quota and not turning on auto top-up. The result and `tried` carry `account_kind`, and every API child adds `--max-budget-usd` (default `1.00`). See [API-key accounts](account-failover.md#api-key-accounts).
    - When API credit is exhausted, omni only notifies and does not buy on your behalf: the account stays skipped until you add credit and then run `omni health clear claude --profile <label>`. See [Credit exhaustion](account-failover.md#api-key-accounts).
  - **vendor reset**: if a claude / cursor consult `rate_limit` parses a vendor reset time from the envelope `detail` (the dispatch layer cannot see the raw stdout/stderr), the ledger `until` uses that time; otherwise it uses today's default cooldown. Structured fields take priority (JSON keys `resetsAt` / `resets_at` / `retry_after` / `retryAfter`, HTTP `Retry-After: N`); text forms (`resets at <ISO or HH:MM>`, `try again in N minutes/seconds`) are best-effort, and if they cannot be parsed it never guesses.
- **Bounded rate_limit retry**: other paths keep a bounded backoff; any Codex / Claude / Grok failure carries a terminal no-retry (`account_retry_safe: false`) and does not do a same-account backoff retry; terminal no-retry provenance on a managed-account request takes priority and cannot bypass the stop-after-tool-activity rule or the Codex / Claude / Grok do-not-rerun rule.
- **usage (observation)**: every successful reply carries a normalized `usage`, with the same set of fields on every backend — `input_tokens` / `cached_input_tokens` / `cache_write_tokens` / `output_tokens` / `reasoning_tokens` / `total_tokens` / `source` / `raw`. Core rule: **a field the backend cannot report is `null`, never `0`**; a reported `0` is kept as-is (that is a measurement). `source` is `provider` / `estimated` / `unavailable` (`estimated` is currently reserved and unused), and `raw` keeps that provider's own usage object. `total_tokens` is never synthesized by summing — each vendor's inclusion relationship among cached / reasoning and input/output differs, and adding them invents a measurement whose semantics are undefined. Getting usage requires the CLI's JSON output mode: agy / grok / claude use `--output-format json`, codex uses `--json` (reply text still comes from the `-o` file), pi uses the `--mode json` event stream; cursor uses `--output-format json` (the `result` field; usage is currently `unavailable`). If the CLI emits output that cannot be parsed, the reply is still returned and `source` is marked `unavailable` — a usage failure must never cost the caller the answer.
- **LOUD failure**: every failure returns a structured `{ok:false, reason}` and is never silent.
- **ADVISORY + UNTRUSTED**: output is always advisory; the caller must sanitize again and ground again.
- **Optional zellij watch pane** (agy / grok / codex CLI): pass `watch_pane` + `zellij_session` + `zellij_tab` on the call to open a floating pane in the given tab that follows CLI output live; the pane closes as soon as the work ends. See "Zellij watch pane" below.

## CLI entry (`omni`)

A second entry to the same provider core: it does not go through MCP, so any shell / harness / scheduler can call it directly. The envelope, model routing, LOUD failure contract, and MCP tools are identical; zero dependencies is unchanged.

Install: `ln -sf <repo>/omni_cli.py ~/.local/bin/omni`

|---|---|---|

| `omni big` | `llm_big_context` | `omni big "instruction" -s /path/doc.txt` |

`omni health` lists, as JSON, the seats that are still cooling down. When a valid lease exists, the `--json` payload also includes `leases`. `omni health lease acquire --token T --pool P --order O --ttl N` writes a lease; `renew` / `release` renew and release it. `omni health flag <model>`
can manually flag a given quota pool; `--profile` selects a profile, and `--until` sets a
Unix or ISO-8601 timestamp. `omni health --probe` runs one
`account/rateLimits/read` against the Codex `codex app-server` (it does not consume a model request), prints
`quota.codex.<profile>` next to the ledger snapshot, and writes the quota under the account key
`codex@<profile>` (if the second window is a weekly window it also writes `codex#week@<profile>`, otherwise `codex#m<minutes>@<profile>`; one observation aligns every time window of that profile): if the vendor has already reset, it only clears
that window's `source=quota` records; if it is still exhausted, it writes `until` as the vendor's `resetsAt`. The same `--probe` also runs one job
`sweep_orphans`, and the payload includes `jobs_repaired` (the ids that were repaired); `--quiet`
also includes the `repaired` count. `omni health --probe --all-profiles`
refreshes the ledger for every known profile on every road (claude / codex / grok / cursor): codex runs a real quota RPC for each profile; claude / cursor send no request and only run the existing
maintain/prune so expired flags disappear. The emitted `quota` is grouped as `{road: {name: ...}}`
(names and quota only, no identity); seats that are still cooling down still exit 0 (advisory).
`--all-profiles` without `--probe` is an argparse error. Health status is also attached to the return value of `list_models()`.

The health ledger is written by default to `~/.local/state/omni-llm/health.json`; 
`OMNI_LLM_STATE_DIR` can point it at another directory. The key is `<pool>@<profile>` (`None` is normalized to
`default`; it is not folded to default because of the CLI road). The bare road name of an account key is that road itself (so the road of `codex@p` is codex, not the dispatch router's openai). Shape is scope: a `<road>@p` account,
a `<road>/<model>@p` model, a `<road>:<bucket>@p` billing pool, a `<road>#<window>@p` time window
(if the second window is a weekly window it is written as `<road>#week@p`, otherwise `<road>#m<mins>@p`. This local-origin flag exists only inside omni, is set only by omni's own code, and is removed before leaving dispatch; it does not appear in MCP / CLI / job output.    (pushes `probe_after` forward by `probe_every`, default 600s, `until` unchanged) and
   continues down the chain. `manual` and `source=quota` entries are not probed.
3. **Expiry**: after `until` has passed, the next locked mutation (including the `maintain`

### Artifact references (issue #22 P1.4)

Large success bodies can return an **opaque artifact reference** instead of the
full text. **Default stays fully inline** (byte-identical for existing callers).

**Trust / honesty**

- Rehydrated artifact content is **untrusted prior LLM output**, not a trusted
  earlier result. Callers must re-ground it.
- Integrity is anchored by the **content-addressed id** (`id = sha256(blob)`),
  which travels in the envelope/conversation **outside** the store. Tampering
  on disk is detectable without any secret key.
- A same-UID writer can poison the store on disk; application crypto cannot
  bound that class of attacker.
- **Deployment requirement:** keep `$OMNI_LLM_STATE_DIR` **outside** every
  agent-lane write allow-set (not a module invariant — operators must fence it).

**Opt-in**

| Surface | Flag / arg | Values |
|---|---|---|
| MCP `llm_generate` / `llm_big_context` only | optional `result_mode` | `inline` (default) · `ref` · `auto` |
| CLI `omni gen` / `omni big` | `--out-mode` (new; never overloads `--out FILE`) | `ref` · `auto` |

- `ref`: any non-empty success `text` is spilled.
- `auto`: spill only when raw UTF-8 `text` **> 65536** bytes (exactly 65536 stays inline).
- Spilled envelope: `text` becomes a bounded preview (first 512 chars + `…[spilled]`), plus `artifact_ref: {id, sha256, text_bytes, expires}`. MCP `structuredContent` mirrors the same envelope; `outputSchema` declares `artifact_ref`.

**Store**

- Path: `$OMNI_LLM_STATE_DIR/artifacts/<id>/{meta.json,blob}` — **sibling of** `jobs/`, never inside it.
- Dir mode `0700`, file mode `0600`; atomic publish (temp dir + rename via dir fds).
- **Content-addressed id:** `id = sha256(blob).hexdigest()` (64 lowercase hex). Identical content is idempotent (refresh expiry).
- Read recomputes the digest of the blob actually read and requires it to equal the requested id → LOUD `artifact_corrupt` on mismatch. `meta.sha256` is advisory only.
- Path ops use `O_NOFOLLOW` / openat dir_fd discipline; mutators never chmod a path before proving it is a non-symlink owned directory.
- Per-artifact cap: `OMNI_LLM_ARTIFACT_MAX_BYTES` (default 32 MiB). Store quota: `OMNI_LLM_ARTIFACT_STORE_MAX_BYTES` (default 512 MiB) and max entry count. Over-cap create refuses **before** writing.
- **Locking:** every operation on an *existing* entry takes a `fcntl.flock` on the artifact directory fd (`LOCK_SH` for read; `LOCK_EX` for remove/gc/reclaim and create’s refresh-or-replace path), then re-checks that the name still resolves to the same inode before acting — so a concurrent collector yields `artifact_not_found`, not a false `artifact_corrupt`. Public read/create/remove use non-blocking acquisition with a short **total** bound (~250 ms) and surface `artifact_busy` rather than hanging; collectors (`gc` / reclaim) take a **single-shot** non-blocking attempt and count `skipped_busy` immediately (never spend the retry budget per entry). A stuck holder can starve a single entry until it exits (lock dies with the process). Busy is `EWOULDBLOCK` and, deliberately, `EAGAIN` (equivalent on Linux; accepted as the portable busy signal elsewhere). **Caveat:** the contract assumes local POSIX flock semantics — do not put `$OMNI_LLM_STATE_DIR` on a network filesystem where `flock` is ignored, emulated poorly, or returns `ENOTSUP`/`EBADF`/`ENOLCK` (those fail loud as `runtime_error` on the public and collector paths, never as a silent unlock or pretend `artifact_store_full`).

**TTL / errors / GC**

| Env | Default | Meaning |
|---|---|---|
| `OMNI_LLM_STATE_DIR` | `~/.local/state/omni-llm` | state root (artifacts + jobs + metrics + health) |
| `OMNI_LLM_ARTIFACT_TTL_S` | `604800` (7d) | artifact lifetime in seconds |
| `OMNI_LLM_ARTIFACT_MAX_BYTES` | `33554432` (32 MiB) | per-artifact create/read cap |
| `OMNI_LLM_ARTIFACT_STORE_MAX_BYTES` | `536870912` (512 MiB) | store byte quota |

- Read past TTL → `artifact_expired`; unknown id → `artifact_not_found`; tamper/schema fail → `artifact_corrupt`; lock not acquired within bound → `artifact_busy`. Failures are LOUD `{ok:false, reason}` / CLI exit 1 with stable JSON.
- Explicit GC only: `omni artifact gc` (only deletes under `artifacts/`). No opportunistic create-path GC. Unpublished temp dirs and anything under `jobs/` are never touched.

```bash
omni gen "prompt" -m grok-4.5 --out-mode auto
omni artifact read <id>
omni artifact rm <id>
omni artifact gc
```

Output mode (gen / big):

- Default: stdout prints one line of envelope JSON; exit code 0 = ok.
- `--out FILE`: reply text is written to FILE; the envelope keeps only `text_path` / `text_bytes` — fan-out or large output does not fill stdout.
- `--out-mode ref|auto`: opt-in artifact spill (see the section above; independent of `--out`).
- `--plain`: print only the reply text; on failure the envelope goes to stderr, and the exit code is still non-zero.

Passing `-` as the prompt reads stdin (`big` uses `--text-stdin`); the zellij watch pane reuses the same set of `OMNI_LLM_*` env vars.
- **Large stdin volume safety:** for codex, claude, and the agent lane that are fed via stdin, the CLI runner feeds stdin and reads stdout/stderr with concurrent streaming, so large inputs do not block each other. Small prompts on the agy CLI stay as inline argv; above 32 KiB they are sent via a read-only input file inside a private directory, still under the 12 MiB local cap (this is not a provider context guarantee).

### Egress gate (optional, off by default; CONSULT LANE only)

A thin deny-before-send layer for the consult lane: when `OMNI_EGRESS_GATE=1`, each consult seam listed below scans **the strings that seam actually sends** before sending. On a hit it **does not send**, and returns LOUD `{ok:false}` with `detail` starting with `OMNI-EGRESS-DENY [<family>]`. `OMNI_EGRESS_DENYLIST` is optional and points to a file with one literal deny string per line (`#` comments and blank lines are skipped); a missing file fails closed. bare-run (gate off) is the default, and is an intentional gap that does not scan content.

Scan scope (per seam; fields not listed are not scanned):

- `llm_generate` / `llm_big_context` routing layer: `prompt` (big_context has already concatenated instruction + source into the prompt).
- `llm_image` (only via `dispatch.call_tool`): `prompt`, `source_image`, `out_dir` (the latter two are interpolated into the grok CLI image_edit prompt).
- grok consult: `prompt`, ACP text block, and each `resource`'s `text` and `uri` (`uri` is composed from the filename and is rendered to the model). Image-block bytes are not scanned.
- agy subprocess / agy SDK: the prompt string that is sent (the SDK path appends `files=` paths into the prompt before scanning).
- codex / claude / pi / cursor / openai_compat: `prompt` text. openai_compat sends only one user message and has no separate `system`.

The following seams are **not covered by this gate** (intentionally ungated this round, consistent with the consult-lane scope in the CHANGELOG):

- agent lane (`omni agent`)
- job lane (`omni agent start` / jobs)
- codex / claude file attachments (consult `-i` paths and file contents; claude consult does not accept `files=`; agent/job attachments are likewise not scanned)
- direct image-module calls (`providers.grok_image_cli` / `providers.xai_image`, not via `llm_image` dispatch)

**Protected-branch contract (#168)**: omni blocks a fenced child from changing the **local** protected branches (`main`, `master`, and origin's default branch); the remote is the server-side branch protection's responsibility. It applies to every write-mode execution whose workdir is inside a git worktree (`--allow-repo-write` only makes admission mandatory) and is not limited to `--allow-repo-write`.
- **The list lives outside the fence**: the protected list is no longer derived from `.git` content the child can write. The first time omni sees a repo (keyed by the common dir's identity: realpath + `st_dev`/`st_ino`), it records `main`, `master`, and the origin default branch resolved at that moment (keeping the original spelling, for example `Main` or `ReLeAsE/v1`) in `$OMNI_LLM_STATE_DIR/protected-refs/<hash>.json` (`<hash>` is the sha256 of the common dir's `st_dev:st_ino`, **not** the path: the `/System/Volumes/Data/...` spelling and the ordinary spelling of the same directory are one record; the path stored in the record is the ordinary spelling, and comparison uses `stat`'s `st_dev`/`st_ino`, not the string: parent-directory spellings that differ only in case are still the same repo; if the stored path does not exist, cannot be read, or is now a different directory (the repo was moved), refuse) (default `~/.local/state/omni-llm`), and registers that key in the `ledger` in the same directory (the registry). Later executions only read this record and no longer read `refs/remotes/origin/HEAD`. In the following cases a write-mode execution is refused with `fence_path_rejected` and is **not** rebuilt automatically from refs: the record exists but cannot be read, the format is wrong, or the path/device/inode does not match the current repo (the same inode with a different path, for example a moved repo, is in this list); an old record keyed by path (legacy) is always refused with a reset hint, and is neither read nor rebuilt; a **new** repo on the same path (for example a fresh clone, a different inode) is a new first sighting and is registered separately; the record is **missing** but the key is already in the registry; the registry is missing but records remain in the directory; the record exists but the registry does not have it. Only when the registry has no such key (a true first sighting) does it register and record. The message includes the paths of the record and the registry; the explicit reset method is, after confirming the repo, to delete that record and its line in the registry at the same time (or the whole `protected-refs/` directory). `OMNI_LLM_PROTECTED_BRANCHES` is **not** a recovery path for these refusals. The record and the registry are deny-write for **every** fenced child (whether or not the workdir is a git repo, and whether or not `--read-only`), and every ancestor directory of the record directory gets an additional literal deny (blocking rename/moving the whole tree). If the state-directory path goes through a symlink, it is walked by hand, segment by segment, with `readlink`, and **every** path traversed (each hop, the path it points at, and each of their ancestor directories, both spellings) gets a literal deny; if the walk cannot finish (the link cannot be read, or a loop), refuse, so even when `OMNI_LLM_STATE_DIR` is inside the workdir it cannot be touched (verified by a live probe). On the first record, an unreadable `origin/HEAD` is still a refusal. A `--read-only` execution neither reads nor writes the record or the registry (it cannot change a ref, and keeps the original derivation from refs). Operator override: `OMNI_LLM_PROTECTED_BRANCHES=release,hotfix` (comma-separated; `main`/`master` are always kept) names the protected list directly, the answer comes from the override and does not read refs; but every writable first contact still leaves a record (after the override is removed, the record answers, rather than derivation from refs): if `origin/HEAD` can be read, record "the derived names ∪ the override"; if it cannot be read clearly (garbage content, a loop, an ordinary file, or a raw object id), record `main`, `master`, plus the override; an existing record is not overwritten. When the record or the registry cannot be read or written (a broken registry, or a write failure), write-mode admission is **refused** even if an override is set; the recovery method is the explicit reset above (delete the record and that registry line). An illegal value is refused, and the value in the message is masked and then truncated (host-exec prints it directly). Because the list no longer comes from `origin/HEAD`, `git remote set-head` inside the fence works again (the deny on `refs/remotes/origin/HEAD` has been removed; denies on protected-branch refs and their parent directories remain as defence in depth; the `commondir` and `gitdir` files of a linked worktree and of the main git directory are also deny-write, so a child cannot point verification at a stand-in repo).
- **Post-execution verification (agent lane)**: before spawn, the parent process outside the fence (`git_safe`) lists every ref with an **explicit `--git-dir`** (the canonical common dir pinned before spawn; it is not rediscovered from the workdir, so a linked worktree rewriting its own `commondir`/`gitdir` or `.git` pointer cannot fool it; a `commondir` file appearing inside the common dir is treated as unverifiable), takes the name and the object id and symbolic target of any ref that matches any protected name **under the same folding rules as admission** (case-insensitive, NFC/NFD; also including refs located under a protected name that could cause a directory/file conflict to hide another ref), and lists them again after the child exits. What is compared is the ref set and the values: a changed value, a new ref (including a spelling that differs only in case or normalization), a deletion, or becoming symbolic always changes the result to `ok:false`, `reason: protected_ref_changed`, and `detail` lists the ref and the before/after values and hints to restore with reflog / `git update-ref`; if it cannot be read afterwards (or the common dir was replaced), the result is `protected_ref_unverified`. This is unaffected by any filesystem technique during execution (for example moving a whole directory that contains loose refs into `refs/heads/`, a symbolic-ref chain, a `packed-refs` rewrite, or writing `packed-refs` unsorted). The comparison runs after the child has been reaped, and it is **the same for a normal exit, a failure, a timeout, an exception, and a cancel (stop)**. On cancel, if a ref changed, the returned envelope is the full `protected_ref_changed` (not a CancelledError), and the job runner does not cover it with `stopped` (an integrity failure takes priority, and detail notes that it was also stopped). Verification covers write-mode executions, including foreman; `--read-only` is not verified. `--allow-main` exempts only **that one ref itself** currently checked out by the workdir (the exact same name; another spelling such as `refs/heads/MAIN` is still a different ref and is still compared); the other protected refs are still compared. A ref whose name matches the protected list, that exists as a file, but that `for-each-ref` cannot list (content that is not an object id, or a dangling symbolic ref) is not treated as "absent"; it is `protected_ref_unverified` (if it already exists before spawn, execution is refused). Before comparison, `killpg` the child's process group (after a normal exit, descendants in the same group whose pipes are already closed stay alive; without clearing them first there is no quiescent point), and after the reply has been read and before any result is returned it is compared once more (regardless of whether the result was originally ok: an integrity failure takes priority over `no_workspace_writes` and `workspace_writes_unknown`, and the job runner's stop handling keeps it too). `omni agent start --allow-main` is now written into the job and forwarded by the runner to the agent lane. An external update unrelated to the run (for example the operator committing to `main` from another checkout at the same time) cannot be distinguished from a change by the child and is reported the same way.
- **Unsupported ref storage formats**: when `git rev-parse --show-ref-format` is not `files` (for example reftable), write mode is refused (both the host fence and the agent lane block it; #164/#169). When a bare repo or a `--separate-git-dir` git directory is the workdir, write mode is refused (a writable workdir itself would otherwise mean the refs are writable).
- **Admission refusal and whole-tree deny**: at write-mode admission (both the host-fence path and the agent-lane path, including `--allow-main` and including detached HEAD), **any** symlink under `<common dir>/refs` (file or directory; `refs` itself counts; a failed check counts too) is refused with `fence_path_rejected` (the message contains "symlink"; `--read-only` is unaffected), because a path deny cannot see through a filesystem alias. Any local ref of a protected name (compared with the same folding rules as admission: case and NFC/NFD, so `MaIn` is `main`; on the agent lane the branch exempted by `--allow-main` counts too) that is a symbolic ref (a single level, a chain, or a dangling target) is always refused. The host fence scans every spelling with `for-each-ref --format=%(refname)%00%(symref)` and adds the original `symbolic-ref` probe of the exact name (to catch a dangling target); the agent lane looks at `%(symref)` in the pre-spawn snapshot. The whole message is masked first (a branch name can look like a key) and then emitted, so host-exec does not print it directly. Git metadata paths (`packed-refs`, `HEAD`, `config`, `hooks`, `refs`, `worktrees`, `commondir`, `gitdir`, and `.git` of each git directory and of the repo) that are symlinks are also always refused (Seatbelt sees the resolved target, so a literal deny on the link itself does not take effect). A loose-ref file whose folded name matches the protected list is read at the start; content that begins with `ref:` is a symbolic ref, and even a dangling target (`for-each-ref` does not list it) is blocked, regardless of spelling. The hardlink check runs on every write-mode return path (including ordinary write mode stopped on a protected branch). `OMNI_LLM_PROTECTED_BRANCHES` that is set but, after stripping whitespace and commas, contains no name (for example `,`) is treated as unset. A failed check of the record directory or the registry (for example a directory that cannot be listed) is always refused with a reset hint, and is not treated as "no record" and then registered. All emitted error text is masked at the boundary: every string field printed by `omni host-exec`, and the agent envelope's `detail` (a single exit). This is so a branch exempted by `--allow-main` cannot reach another protected name through a different name. `refs/remotes/origin/HEAD` is a normal symbolic ref; it is neither checked nor denied (`git remote set-head` works as usual). `--read-only` is unaffected. The repo roots (worktree root, main checkout root, and linked-metadata root) and **every** ancestor directory of them have a literal deny (both spellings), so the whole repo cannot be `mv`'d away. The common dir's `refs` and `refs/heads` are denied whether or not they exist (a repo that has only packed-refs is the same; a directory prepared outside cannot be `mv`'d into `refs/heads`; the cost: when `refs/heads` does not exist, no branch can be created inside the fence). `refs/remotes*` is still denied only when it exists.
- **Nested repos inside a non-git workdir (#187)**: in write mode, when the workdir itself is not a git tree, the whole tree is writable and a nested repo's `.git` is outside the protected-branch rules, so before the child starts the workdir is walked once (breadth-first; symlink directories are not entered). Finding an item named `.git` (a directory, a `gitdir:` pointer file, or a symlink, folded for case and NFC/NFD) or a directory that looks like a bare repo (it has `HEAD`, `objects`, and `refs`) refuses with `fence_path_rejected`, and the message names the first hit (a path relative to the workdir, masked). A failed walk refuses (fail closed): more than 20000 items (`host_fence.NESTED_REPO_SCAN_CAP`), or any directory that cannot be read, writes "could not verify" in the message and notes the cap. `--read-only` is unaffected. A git workdir is scanned the same way before start (#199): other than its own top-level `.git` and linked-worktree pointer files verified to belong to the same repo, any other `.git` or bare repo under the worktree, or a submodule git dir inside `<common dir>/modules`, is refused with `fence_path_rejected`.
- **Core control inside the fence (kernel deny)**: for a protected name that contains a slash (such as `release/v1`), its parent directory `refs/heads/release` is deny-write even when it **does not yet exist** (literal; every case spelling), so the child cannot `mkdir` and cannot `mv` a whole directory in to override the `packed-refs` value (a live probe measured EPERM for both; an ordinary work branch, including a slashed name such as `feature/x`, still commits as usual). The cost: inside the fence, other branches cannot be created under such a directory (for example, when `release/v1` is protected, `release/v2` cannot be created). Execution inside the fence relies on this deny as the control, not on the later comparison. If the state directory is given with a `/System/Volumes/Data/...` spelling, the denies on the record and on each ancestor directory also add the spelling without that prefix (Seatbelt compares only the path after kernel resolution). Each registry line is one JSON object (a path containing CR/LF is safe too).
- **Residual risk**: `killpg` is sent only **after** the leader has been reaped. Between the leader being reaped and `killpg` (milliseconds), if that pgid is recycled by the system, it could theoretically hit an unrelated process group (there is no owned anchor process to pin it; a known residual risk; each execution does `killpg` only once). Descendants that leave the process group with `setsid` are not reached by `killpg` and can outlive the later comparison. Execution inside the fence has the kernel deny above blocking the known techniques, but a foreman execution (unfenced by design) does **not** have this control; this is a documented residual risk. `omni host-exec` replaces itself with `os.execvpe`, and after exec there is no parent process that can verify, so the host-exec path has **only** the list record and the path denies, with no post-execution comparison. A caller that wants the same guarantee must read the same refs itself after the child exits. The record is decided by the refs at the moment of "first seeing the repo": if an unfenced process had already tampered with the repo then, that is what gets recorded. An origin default branch later renamed on the remote does not automatically enter the list (use the override, or delete the record and that registry line and re-record using the reset method above). When the supervisor is `SIGKILL`'d (the last resort after the `jobs.stop` grace period), no process can do the post-execution comparison. A child job produced by `jobs.resume` does not inherit the parent job's `allow_main` (it is not forwarded; the original behavior stays). An unfenced process (same uid) that can write the whole state directory is outside the scope of this defense.

Accepted residuals: the checks are not atomic with the kernel's own path walk; an unfenced process running as the same uid can plant anything and does not need this window; a fenced job can write only inside its own allow-set, and the shared vendor state names are leaf-checked on every spawn; inode reuse after delete+recreate, held descriptors and `st_birthtime` comparison are deliberately not implemented.

Codex success semantics (issue #51): `codex exec` treats an internal command failure as a recoverable event, and the outer process still exits 0. A run in which every command was blocked used to return `ok:true` anyway, and what you got was only the agent's account. The criterion now is: **at least one command ran, every one of them failed, and at least one of them exited 71** (sysexits `EX_OSERR`, the return value when `sandbox-exec` cannot apply a profile, meaning that command never actually started). Only then does it return `ok:false` + `reason: "runtime_error"`.

The criterion reads only `exit_code` and `status` in the `--json` event stream. **It does not read command output, the command's own argv, the process stderr, or the `-o` reply file.** This is a structural guarantee, not an item-by-item exclusion: any pipe the caller or the agent can write into cannot touch this decision. For that reason the sync lane now also carries `--json` (previously only the job lane did); otherwise the sync lane has no machine-readable signal and can only read codex's human transcript, and that transcript copies **the caller's prompt verbatim at the start** (printed before it is sent to the model), so a task such as "please fix that sandbox bug" would be judged a failure by its own problem statement. `--json` and `-o` do not conflict (codex-cli 0.147.0 `exec --help`); the job lane has run this way since #22. The sync lane's stdout therefore becomes JSONL, and when `-o` is empty the reply is taken from the `agent_message` event; the raw JSONL is not returned. A command that simply fails (for example a red test) is still a normal result and still returns the agent's answer. Two known tradeoffs (both biased toward "hand over the agent's answer"): one command that happens to succeed covers a judgment that everything else failed, and a block that happens before the first command event is not detected.

Grok stall watchdog (job lane): grok sometimes prints a final line `type:"result"` and then the process does not exit. After that line is seen, if there is no new stdout byte for `OMNI_LLM_GROK_STALL_GRACE_S` consecutive seconds (default 720; it must be a finite number greater than 0, otherwise the default is used and a log line is recorded), omni sends SIGKILL to the whole process group. When the result line means success (`is_error` is not true and `subtype` is absent or `success`), it follows the ordinary success path, `ok:true`, plus an extra `termination: {"reason":"stall","elapsed_s":N,"marker":true}`; otherwise it returns `ok:false, reason:"stall"` and `partial_reply`. Grok's wall-clock timeout (both lanes) now also carries `partial_reply` (the reply produced before truncation, with known credentials already masked; past 65536 characters the tail is kept and `partial_reply_truncated:true` is added) and `termination: {"reason":"timeout",...}`. Grok on the sync lane (`--output-format plain`, no marker line) has no watchdog, only the wall-clock timeout. Other providers' envelopes are unchanged. Known limit: descendants that call `setsid` are outside the group kill; the host-exec path has no omni watchdog.

A handoff successor uses the same `omni agent start`: `--model` / `--effort` / `--workdir` / `--permission-mode` are turned into each harness's own flags. claude carries `--model` / `--effort`; `--permission-mode` is passed verbatim only when it is not default (omitting it or `default` does not send this flag: the claude CLI has no `default` choice). codex carries `-m` and `-c model_reasoning_effort=<e>`, and the task goes on stdin (argv ends with `-`; the job lane already feeds it this way and does not need `</dev/null>`). Under foreman, `plan` is `--sandbox read-only`, `bypassPermissions` is `--dangerously-bypass-approvals-and-sandbox`, and the rest is `--sandbox workspace-write`. grok carries `--model` / `--reasoning-effort`; `plan` is a LOUD `unsupported_permission_mode` (the same reason as `--read-only`: the strict sandbox cannot separate reads from writes; see `unsupported_read_only` above), `bypassPermissions` is `--sandbox worker --always-approve`, and the rest is `--sandbox strict`. Measured (claude_code 2.1.272): the CLI `--effort` overrides `modelSettings.<model>.effortLevel`; settings take effect only when the flag is absent; a model with no effort support has no `effort` key on the first assistant line of the transcript, and a read-back must be written as `unknown` and must not be guessed.

`--foreman` is an explicit unfenced successor mode; the default stays fenced. Only claude/codex/grok are supported; `pi` / `cursor` are a LOUD `foreman_unsupported_provider`. After it is added, `fence_requested` is false (the claude envelope `fence` is `none`; codex/grok are `vendor`, the same as today's `--no-fence`). The claude argv drops `--setting-sources project`, `--dangerously-skip-permissions`, and `--strict-mcp-config`, and carries `--permission-mode` instead. codex does not get the kernel wrap and carries the sandbox flags from the previous section. grok carries the sandbox flags from the previous section. A foreman child does **not** set `OMNI_LLM_DEPTH` (the successor is itself the root and will dispatch `omni agent` again; recursion protection only blocks an unattended agent-to-agent chain) and does **not** clear `OMNI_LLM_NOTIFY_CMD` / does not set `OMNI_LLM_NOTIFY_QUIET` (health flags must reach the operator). Except for a foreman successor, every spawn clears the operator's notify sink in the shared builder. `--foreman --read-only` is a LOUD `foreman_requires_write_lane`. Without this flag, behavior is exactly the same as today.

### `omni --version` and `omni contract` (version and interface contract)

Downstream tools (external plugins and dispatch scripts) do not import omni modules and do not assume a checkout path. They ask the installed `omni` directly:

- `omni --version` prints `omni <version>` (for example `omni 0.10.0`) and exits with 0. The version string has a single source, `providers/version.py`. The MCP server's `serverInfo.version` is taken from it as well.
- `omni contract` prints exactly one JSON object on stdout and exits with 0. It is pure introspection: it does not connect to the network, does not start any vendor binary, and does not create or write the state directory. Keys: `name`, `version`, `contract_version`, `cli.subcommands` (derived from `build_parser()` and sorted), `mcp.server_name` and `mcp.tools` (derived from `TOOLS` in `providers/dispatch.py` and sorted), `dispatch_exec.result_record_version` / `providers` / `exit_codes` (rc string → short meaning), and `state_dir` (the state directory that is actually in effect, honoring `OMNI_LLM_STATE_DIR`; it reports the path only and does not create it).
- `contract_version` is incremented only when any item listed in the contract has a **breaking change** (removing or renaming a subcommand or MCP tool, changing the meaning of an exit code, changing the result-record `version`, or removing or changing the type of a key). Adding a subcommand, tool, or key does not increment it.
- How downstream checks: first see whether `version` meets the required minimum, then use `omni contract` to confirm that the required subcommands (`cli.subcommands`) and tools (`mcp.tools`) are present, rather than inferring that from the version number.

### `omni dispatch-exec` (grok dispatch execution stage)

Synchronously runs the grok execution stage of `dispatch-external.sh`, replacing its perl watchdog with one call. Caller: external `dispatch-external.sh` (enabled by `DISPATCH_GROK_VIA_OMNI=1`; on by default when going through `dispatch-chain.sh`). It accepts only `--provider grok`; `--mode read-only|workspace|strict` (default when omitted: `read-only`). **macOS only**: on non-macOS, every mode returns 6 before doing any work (`omni dispatch-exec: credential source unproven for resolved login`). There is no longer a path that starts grok directly. Required flags: `--model --effort --workdir --prompt-file --prompt-sha256 --outfile --invocation-id --result-file --login --config-dir --parent-pid`, plus five time limits `--wall-s --stall-grace-s --kill-grace-s --poll-s --canary-timeout-s` (no defaults; a missing one is argparse rc 2). Flow: in read-only mode, run the canary first (a fresh private 0700 probe, proving through the same `omni host-exec --provider grok --workdir W --read-only` that writes are refused; failure is rc 8 and prints `dispatch-external: read-only containment refused: ...`; if the grok real executable cannot be found, return 4 before touching the outfile and print `capacity incident: grok binary not found ...`) → truncate `--outfile` and write one line `dispatch-containment: layer=... sandbox=... canary=... canary_at=...` → print a launch trace on stdout → execute. The child process is `omni host-exec ... -- <grok absolute path> --sandbox off ...` (the fence program is unchanged). The child's stdout and stderr are connected directly to the outfile (raw bytes, no masking, no footer). The supervisor's own stdio and the result record do not go into the outfile.

**Result record**: `--invocation-id` (32 lowercase hex characters) binds this call. `--result-file` must be an absolute path, its parent directory must already exist, the file itself must not yet exist, and it must not be the same file as the prompt, the outfile, or the trace-prompt (otherwise rc 2 and no record is written). At the end it writes exactly one terminal record (an O_EXCL 0600 temporary file in the same directory → write the complete JSON → flush + fsync → `os.replace` → fsync the directory when possible; no temporary record is written). If it cannot be written: rc 125, and one stderr line `omni dispatch-exec: result record not published`. The record is one JSON object whose keys are exactly `version` (1), `invocation_id`, `outcome` (`vendor_exit|stall|wall_timeout|signal|refused_before_spawn|supervisor_failure`), `detail` (`none|arguments|containment|credential_unproven|prompt_mismatch|launch_unavailable|parent_died|start_unknown|internal`), `spawned`, `vendor_rc`, `vendor_signal`, `signal`, `exit_code` (equal to omni's own exit code), `elapsed_ms`, and `marker`. `spawned=false` only when omni never created a process that might run the vendor (the canary probe does not count). The child is always a host-exec wrapper today, so after work begins it is always `null` (never `true`). A wrapper return of 126/127 or an OSError at start is recorded as `supervisor_failure/start_unknown`. **When the record is missing or malformed, the caller must not retry automatically.**

**Credential pinning**: `--login` must be `xai`. `--config-dir` must be a directory that contains `auth.json` (a regular file, not a symlink, owned by this user, a JSON object with a non-empty string `key` or `refresh_token`); otherwise rc 6. The child environment takes host-exec's allowlist (`allowlisted_child_env(env, "grok")`), then removes every name that `provider_accounts.account_env` strips for grok (including `XAI_API_KEY` / `GROK_API_KEY` / base-URL kinds), drops `OMNI_LLM_CHILD_ENV_PASS` (the allowlist is computed only after this variable is removed, so none of the names the operator listed in it can enter the child) and every `PYTHON*` name, and sets `GROK_HOME` explicitly to the realpath of `--config-dir`. The canary uses the same environment. The host-exec wrapper itself is a Python process and runs before the fence, so the wrapper and the canary wrapper are always started as `<sys.executable> -E -s omni_cli.py host-exec ...` (`-E` ignores `PYTHON*`, `-s` skips the user site; `-I` is not used, because it would move the script directory out of `sys.path` and break the `providers` import). The vendor's argv[0] is the grok absolute path that host-exec itself resolved (`kernel_sandbox.resolve_agent_binary`), so what host-exec runs is the file that was checked. Credentials are verified again after the canary and before spawn. **Prompt**: `--prompt-sha256` is the sha256 of the scanned prompt's original bytes. The file is read only once. A hash mismatch, a NUL, a trailing LF, or invalid UTF-8 is always rc 2 (`prompt_mismatch`). No bytes are stripped. The prompt on argv is byte-for-byte identical to the original bytes via `os.fsencode`. **Caller death**: if `--parent-pid` (greater than 1) does not match `getppid()` at the start, rc 125 (`parent_died`). While running (including the canary), every poll slice checks again. On a mismatch, the child is torn down as if a signal had been received, no watchdog line is written, and the record is `supervisor_failure/parent_died`, rc 125. **Cancellation**: the same signal gate covers the entire call and is entered at the first step of `main` (argument parsing and validation, the canary, the gap between canary and start, and writing the record are all inside it). The first HUP/INT/TERM received decides `outcome=signal` and rc 128+n (if it arrives during the canary, the canary is torn down and `spawned=false`; if the id or result-file is unavailable, it only returns 128+n, writes no record, and there is no KeyboardInterrupt traceback). Whenever `--invocation-id` and `--result-file` can be scanned directly from argv and are usable, any argparse failure (a flag missing its value, an unknown flag) writes `refused_before_spawn/arguments`, `spawned=false`, rc 2. Before writing any refusal or failure record, the caller is checked again. If the caller is already gone, the record is always `supervisor_failure/parent_died` (`spawned=false` before work begins, `null` afterward), rc 125. Caller death takes priority over a refusal decided in the same window. Once the outcome is decided (a refusal or the child ending on its own), a signal that arrives later while the record is being assembled and published is discarded. The decided outcome does not change.

The watchdog matches D: a marker is one line in the outfile that ends with a newline, is strict UTF-8, is a JSON object, and has a top-level `type == "result"`. After that, any newly added bytes in the outfile (including stderr) restart the quiet clock. Both the quiet clock and `--wall-s` count only active time. A decision is made every `--poll-s`: the interval since the previous poll charges at most `poll_s+1` seconds to active, and the excess is charged to paused (the whole dispatch tree paused together, host sleep, an overly long scheduling delay; a clock stepping backward adds nothing). The stretch in which the worker has stopped on its own while the supervisor is still running still counts as active. When `now-t0` reaches `4 * --wall-s`, it is first closed as a wall-deadline and marked `ceiling=yes`, then grace, then wall. When grace and wall are both true, grace wins. If the child ends on its own, its status is returned (128+sig if it was killed by a signal), and no line is added. When the watchdog fires (D `terminate_group`), it first sends TERM to the process group and to descendants whose identity was matched, waits at most `--kill-grace-s` (a child that can exit cleanly does not have to wait the full time), then KILLs whatever is still alive, and returns 9 (marker already present) or 10 (no marker). It appends exactly one line to each of the outfile and stderr: `dispatch-watchdog: reason=<completed-then-hung|wall-deadline> elapsed=N marker=<yes|no> active=N paused=N` (and appends ` ceiling=yes` when the 4× wall-clock ceiling applies). A vendor return of 9/10 on its own is passthrough and adds no line. On HUP/INT/TERM (D `on_signal`), it KILLs the process group directly, sends TERM to descendants and then KILL after the kill grace, writes no line, and returns 129/130/143 (the result record is `signal`). A watchdog fire is recorded as `stall` (9, grace with a marker already present) or `wall_timeout` (active time reached `--wall-s`, or wall-clock reached 4×). The vendor's own 9/10 is recorded as `vendor_exit`. Known limitation (the same as D): descendant processes that call `setsid`, or that were reparented before the snapshot, cannot be reached.

### Job-lane images (`--image`, issue #18 P4)

`omni agent start --image <path>` is **repeatable** and **job-lane only** (not on bare synchronous `omni agent` this batch). Each path must be absolute, under `OMNI_LLM_SOURCE_ROOTS`, and carry an **image extension** (png/jpg/jpeg/gif/webp — the same `FILES_IMAGE_MIME` table the consult lane fences on; a non-image refuses the start with `reason: "unsupported_files"` before anything is copied). The job lane does **not** take text attachments — inline text `resource` blocks are a consult-lane grok feature only (see `files` above). On start, omni reads the bytes once through the existing O_NOFOLLOW fence and writes an immutable copy under `<workdir>/.omni-attach/<job_id>/` (per-file cap 5 MiB, total 20 MiB). Backends consume the **copy**, never the original path. Fence/cap failures refuse the start with `reason: "unsupported_files"` (job dir exists, `state=failed`, refusal is `result.json`, no process spawned). `.omni-attach/` is appended to the workdir's `.git/info/exclude` when the workdir is a git repo (tracked files untouched).

**Honesty note:** workdir-drop of the copy path only gives file **ACCESS** for claude/grok (path listed under a trailing `[attached images]` block in the prompt / `prompt.txt`). **Codex `-i <copy>` is the only true vision path in the job lane.** Resume does **not** restage parent images — a child job's `images` list stays empty unless the resume caller passes new ones (`resume()` itself never does).

`resume` opens a **new** child job (`resumed_from=<source>`), and the backend argv appends the parent's `session_id` (codex: `exec resume <id>`; claude: `-r <id>`; pi: `--session <id>`; grok: `--resume <parent> --fork-session --session-id <child>`). When the source is non-terminal, `session_id` is empty, the workdir git pin has drifted (including the all-null pin of a non-git workdir), the source `resume.lock` is held, or another non-terminal job exists in the same workdir, it returns `{"refused": ...}` and does not create a job. `--allow-drift` skips the pin check. **Limit (P3):** this batch does not capture the child `session_id` of a claude / pi resume (it stays null), so another claude / pi resume cannot be chained after it; codex/grok can be chained.

Content blocks are persisted **complete and masked**: a block's start, deltas and stop are held until the block stops, the delta texts are joined into one value, known credential values are masked in that whole value, and the block is written as its start, one delta per kind with the masked text, and its stop (a tool call's input is such a block of `input_json_delta` events). Single-word tasks named exactly `start/status/result/tail/stop/jobs/resume` must be invoked through the synchronous lane; different phrasing or quoting cannot help — they are reserved verbs.

`<job>` may be a full job directory or a job id alone. The supervisor uses `job.lock` as the liveness signal, and `result.json` is written before the terminal state; a stop result uses a separate `reason: "stopped"`. A job whose lock is still held, or whose startup grace has not elapsed, is left untouched.

If a large file is already on disk, prefer the path, so the whole payload is not stuffed into MCP JSON:

| | `text` | `source_path` |
|---|---|---|
| Use | short text, a just-computed fragment | a local PUBLIC UTF-8 text file |
| Mutual exclusion | **one of** with path | **one of** with text |
| Prerequisite | none | env **`OMNI_LLM_SOURCE_ROOTS`** must be set (absolute-path roots, separated by `:` or `,`) |

```bash

```

```json
{
  "instruction": "summarize the key points",
  "source_path": "/Users/you/public-staging/transcript.txt"
}
```

Rules (Codex / Owner final):

1. If `OMNI_LLM_SOURCE_ROOTS` is unset → path mode is **disabled** (`error_code: source_path_disabled`).
2. The path must be inside an allowlist root; outside a root it does **not** leak whether the path exists (`source_path_not_allowed`).
3. A file not found **inside** a root → `source_not_found` (a deliberate limited existence signal; detail does not include the full path).
4. Absolute path, regular file; opened with a root dir-fd plus per-component `openat`/`O_NOFOLLOW` (resistant to parent-directory symlink TOCTOU); UTF-8 strict; per-file and composed-prompt caps are 12MiB each.
5. The file is read **by the server** before it reaches the provider; the Grok/Codex sandbox does **not** cover this read. The path is not a capability grant; the roots are.
6. **Different** from agy `files=` (multimodal attachments): `source_path` is a plain-text SOURCE shared by every backend.

## Grok backend (xAI)

- **Subscription-backed, zero API key**: `grok-*` models use **Grok Build CLI**'s own OAuth login (run `grok login` once in a real terminal and bind your SuperGrok / X Premium subscription). They do not use `XAI_API_KEY` and do not go through a metered API — the same shape as `agy` for Gemini.
- **Model-prefix routing**: A model name that starts with `grok` (for example `grok-4.5`) is automatically routed to the Grok Build CLI; other names follow the original route (agy / OpenAI / local). `effort` maps to `--reasoning-effort` (alias `--effort`); legal values are `low` / `medium` / `high` / `xhigh` (grok 1.0.4 live enum). If omitted, the flag is not passed.
- **Full consult prompt**: Grok consult always passes `--verbatim`, so the `--prompt-file` and `--prompt-json` paths keep the full prompt. If the installed CLI does not support this flag, consult fails explicitly along the existing non-zero exit path; it does not drop the flag and fall back to a call that might truncate the prompt.
- **Hardened into a kernel-sandboxed plain-text pipe**: On macOS, omni's shared host Seatbelt wraps the entire Grok process; the inner vendor sandbox is turned off only after the outer verify holds, and containment does not depend on Grok's own version or claims. It still passes `--cwd <throwaway empty directory>` + `--no-memory` + `--disable-web-search`. **Tools**: `--tools todo_write --disallowed-tools todo_write,search_tool,use_tool` clears the tool set (an empty `--tools ""` is treated by Grok as "unset"; measured behavior yields 25 tools, including shell and file writes); output is switched to `--output-format streaming-json` and the session is pinned with `--session-id`; omni reads Grok's own stdout line by line and decides: each line must be a JSON object with no duplicate keys, and event types and fields must all be on the allowlist; `available_commands` must declare empty `tools` (`commands` may only be a string list of slash-command names), no `tool*` event may appear, there is exactly one `end` at the end, `sessionId` is this run's id, and `stopReason` is `end_turn`; usage copies only integer counts on the allowlist. A non-empty tool set or a tool call is a LOUD `tool_containment_failed`; any other mismatch (unknown event, missing declaration, a different session) is `tool_containment_unverified`, and the reply is never released; `thought` does not enter the reply; what is released is the verbatim concatenation of `text` events (not stripped; only all-whitespace counts as `empty_response`), and events are split into lines only on `\n`; a rejected detail contains only fixed phrases and counts, and contains no stream content. Before the decision, stdout does not enter the error detail and does not enter the watch pane (`run_cli(watch_stdout=False)`). The child process may write `$GROK_HOME/sessions/`, and that is not used as evidence. **Global instructions**: the host fence deny-reads the `AGENTS.md` / `CLAUDE.md` family of filenames and each of their `rules/` directories under `$GROK_HOME`, `~/.claude`, and `~/.cursor` (measured: Seatbelt literals are case-insensitive and also block symlinks via those names; the names and the final targets of symlinks inside `rules/` are denied separately; if an instruction file has a hard-link alias, or any syscall fails during the scan (the scan itself resolves symlinks with `lstat` / `readlink` / `listdir` and does not use `realpath` or `os.path` predicates; the only exceptions are when the root directory does not exist, or the final target of a dangling symlink does not exist, and a second lstat confirms it), it is a LOUD `fence_path_rejected`), so a headless session does not attach the user's interactive instructions; `--rules` only appends, and `GROK_CLAUDE_*_ENABLED=0` also cannot block `~/.claude/Claude.md`, so this relies on the kernel deny. The check recomputes the full entry list from the `GROK_HOME` the child process actually received; a missing entry, or a later read allow that covers it back, is a LOUD `fence_unavailable`; if `--config-dir` and `GROK_HOME` disagree, or either is a relative path, it is rejected; the cover-back check is case-insensitive and also compares the spelling after resolving symlinks (`/tmp` is equivalent to `/private/tmp`); `omni host-exec`, the agent lane, and image edit share the same policy. `[paths] extra_rule_dirs` in `config.toml` is outside the deny scope, and non-Darwin has no such deny. The host policy is not global network isolation, and it does not replace the caller's policy of "send only public data".
- **Fallback chain**: `"grok-4.5,Gemini 3.5 Flash"` follows terminal no-retry verdicts and the [account-selection contract](account-failover.md). A failed child attempt stops the current request; a new request selects an eligible account.
- **⚠️ A running MCP server must be restarted to pick up the new backend**: The old server process attached to Claude Code does not automatically load the new code; it takes effect only after you restart Claude Code (or kill that server process so it reconnects).

## Codex backend (OpenAI, subscription-backed)

- **Subscription-backed, zero API key**: Names that start with `codex/` use the **OpenAI Codex CLI** login (run `codex login` once in a real terminal and bind your ChatGPT / Codex subscription). They do not use `OPENAI_API_KEY` and do not go through a metered API — the same shape as `agy`/`grok`. Non-interactive `codex exec` sends the prompt on stdin and uses `-o` for the reply (output-last-message, taking only the model's last message; banner/metadata go to stderr and are not mixed into the reply).
- **Model-prefix routing**: `codex/<model>` is automatically routed to the Codex CLI, and the `codex/` prefix is stripped and used as `-m <model>` (for example `codex/gpt-5.6-sol` → `-m gpt-5.6-sol`); other names follow the original route (agy / OpenAI / grok / local). `effort` defaults to `high` (you may pass `minimal`/`low`/`medium`/`xhigh`/`max`); MCP `llm_generate` / `llm_big_context` and `omni gen` / `omni big` / `omni agent` all take the same parameter name.
- **Multiple accounts**: `account_profile=alt` reads `CODEX_HOME_ALT` (it must be an existing directory). The child-process `CODEX_HOME` for consult and the agent lane points there; Darwin's kernel fence (the same for consult and the agent write lane) adds that realpath to the write/read allow-set (only this one; the default `~/.codex` is not additionally allowed), and re-resolves it once when the fence is built: inside the home-directory tree only `~/.codex-<name>` is accepted, otherwise LOUD `fence_path_rejected` (issue #102). If it is unset or is not a directory → LOUD `unsupported_profile` (the detail names the variable). When no ring is configured, `default` does not strip the environment and does not change the fence; a managed ring's `default` keeps the default fence admission, pins the actual home, and clears sibling and API-key overrides.
- **⚠️ Consult isolation (Darwin, one Seatbelt layer, #51)**: The shared host helper verifies first, then wraps; only after the outer layer is confirmed to hold does it remove the inner `--sandbox read-only` and pass bypass, avoiding nested `sandbox_apply` rc=71. If wrap, verify, or inner-disable fails at any step, it is a LOUD rejection, and it never falls back to an unwrapped vendor argv. Non-Darwin keeps the existing vendor `--sandbox read-only` baseline: it does not block reading the whole machine, and write escapes were measured on both 0.147.0 and 0.154.0, so it can only be treated as best-effort. The host policy keeps provider HTTPS and is not global network isolation; an empty tempdir and vendor flags remain extra surface reduction, not the basis of containment.
- **Fallback chain**: `"codex/gpt-5.6-sol,Gemini 3.5 Flash"` follows terminal no-retry verdicts and the [account-selection contract](account-failover.md). Any Codex failure (managed, pinned or default, including one before the child starts) ends the current request, and so does a Claude or Grok failure carrying terminal no-retry provenance: no same-account retry, no other account, no later seat or provider (only `account_exhausted`, which starts no task child, moves on). A quota, auth or account-unavailable failure also cools the account, so the next request selects an eligible one; other failures follow the crash streak. Other providers keep their backoff and fall-through.
- **⚠️ A running MCP server must be restarted to pick up the new backend**: Same as the Grok section.


## Claude backend (Anthropic, subscription-backed)

- **Subscription-backed, zero API key**: Names that start with `claude/` use the **Claude Code CLI** login (run `claude auth login` once in a real terminal and bind your Max subscription). Consult is a one-shot `-p`, `--strict-mcp-config` does not load MCP, and `--tools` limits built-in tools to Read/Grep/Glob and disables write/execute/network/sub-agent tools; `OMNI_LLM_DEPTH` is the recursion guard.
- **Multiple accounts**: `account_profile=alt` reads `CLAUDE_CONFIG_DIR_ALT` (it must be an existing directory; inside the home-directory tree only `~/.claude-<name>` is accepted, the same as codex). The child-process `CLAUDE_CONFIG_DIR` for consult and the agent/job lane points there; the Darwin agent kernel fence treats that realpath as the vendor root (read R and `R/.claude.json`, sessions are written under `R/projects/<encoded>`, deny-read `R/projects`; the default `~/.claude` is not allowed at all). The default `~/.claude` cannot be a profile; under the home directory only `~/.claude-<name>` is accepted (non-empty after the hyphen). If it is unset or is not a directory → LOUD `unsupported_profile` (the detail names the variable). That directory must first be logged in interactively once with `CLAUDE_CONFIG_DIR=<dir> claude auth login` (Keychain entries are separated by a hash of the config dir); if not logged in, it is a LOUD `auth_error` and names the variable. `default` does not strip the environment and does not change the fence.

## Cursor backend (riding a subscription)

- **Subscription or API key**: Names that start with `cursor/` go through the **Cursor Agent CLI**. The executable only recognizes `cursor-agent` (pin the path with `OMNI_LLM_CURSOR_BIN`). **Do not** run `agent` — on this machine that name is the Grok Build CLI. Login: `cursor-agent login`, or set `CURSOR_API_KEY` (do not put the key in argv).
- **Multiple accounts**: `account_profile=alt` first looks at `OMNI_LLM_CURSOR_CONFIG_DIR_ALT` (the same path as today's env opt-in: the caller's directory, and it is not deleted); otherwise `CURSOR_API_KEY_ALT` (written only into the child-process env, not into argv, not into the envelope, and not logged). When both are set, the config dir wins, and the key is still passed along. Inside the home-directory tree only `~/.cursor-<name>` is accepted; otherwise LOUD `unsupported_profile` (producer) / `fence_path_rejected` (fence). Paths held by the launcher (jobs root, system temp root, that is the dirname of mkdtemp) are allowed by the allowlist. On darwin, Cursor login lives in the Keychain, so switching accounts cannot rely on a config dir. If neither is set → LOUD `unsupported_profile`.
- **Fable / Sol**: `cursor/fable` → `--model claude-fable-5-1`; the `cursor/sol` alias is `gpt-5.6-sol`, and when effort is omitted the argv is `--model gpt-5.6-sol-medium` (see below). A full slug is passed through unchanged (`cursor/claude-fable-5`, `cursor/gpt-5.6-sol-high`). `cursor/gpt-5.6-sol` does **not** fall through to OpenAI HTTP. An unprefixed `gpt-5.6-sol` still goes to openai, and that behavior is unchanged.
- **`effort` → model slug**: `cursor-agent` has **no** effort flag; strength is encoded in the model id. The public `effort` parameter is unchanged and is converted inside the cursor channel: `cursor/sol` + `effort=xhigh` → `--model gpt-5.6-sol-xhigh`, and the `model` in the success envelope is also `cursor/gpt-5.6-sol-xhigh` (a second call lands on the same seat and the same strength). When `effort` is omitted, a base in `CURSOR_DEFAULT_EFFORT` (`gpt-5.6-sol` / `luna` / `terra`) is folded into `medium` (the catalog no longer has a bare id); argv for every other base is unchanged. A trailing `@<token>` on the model remainder is equivalent to `--effort` (example: `cursor/sol@high`); a conflict with `--effort`, or an illegal token, is LOUD `unsupported_effort`. The same `@<token>` shorthand now also applies to grok / claude / codex / pi (not only cursor); conflicts and illegal tokens are likewise LOUD `unsupported_effort`. The lookup table is `CURSOR_EFFORT_SLUGS` in `providers/config.py` (taken from `cursor-agent --list-models`, CLI 2026.09.08-6caf4ff snapshot; `gpt-5.5` spells `xhigh` as `extra-high`, and an older family such as `claude-4.6-opus-thinking` places `-thinking` **after** the strength, both handled by `CURSOR_EFFORT_SLUG_OVERRIDES`; the whole table is pinned entry by entry by the catalog snapshot `tests/fixtures/cursor_models.txt`). Three cases are always LOUD `unsupported_effort`, with no silent downgrade: (1) the family has no effort variant (example: `composer-2.5`); (2) the family cannot accept that token (example: `claude-opus-5` only goes up to `high`); (3) the slug itself already encodes a strength (example: `cursor/gpt-5.6-sol-xhigh` also passed with `effort=`) — pass the base slug instead, or drop `effort`. Account catalogs differ: a slug that is in the table but missing from your account fails LOUD on the CLI side and does not quietly switch models.
- **A per-run `CURSOR_CONFIG_DIR`**: `cursor-agent` writes "which model was selected + that model's parameters" into the config directory and reads them back next time. Sharing `~/.cursor` with a human **pollutes both ways**: one headless consult overwrites the default model of your interactive session, and a base slug without effort (`cursor/sol`) in turn inherits the strength you last picked by hand — the same call produces a different strength on a different machine or at a different time. Therefore every consult run opens a temp config dir and deletes it when finished; as a side effect, the consult prompt is no longer written into `~/.cursor/chats`, and the global MCP in `~/.cursor/mcp.json` is not loaded. **darwin login is unaffected** (credentials are in the Keychain, not in the config directory; this has been verified live) — but if another platform stores the token inside the config directory, isolation turns it into a logged-out state. On that kind of machine, set `OMNI_LLM_CURSOR_CONFIG_DIR` to `~/.cursor-<name>` or to a directory outside the home-directory tree, or use `CURSOR_API_KEY` instead. To share one fixed directory, only `~/.cursor-<name>` or a directory outside the home-directory tree is accepted; set `OMNI_LLM_CURSOR_CONFIG_DIR`. A directory set that way is treated as the caller's, and **it is never deleted on any path**. A relative path is expanded to an absolute path against the omni process cwd (not the workspace — that one is deleted when the run finishes). If a temp config dir cannot be deleted (a file is busy, and so on), stderr prints `cursor_tempdir_left_behind`. It is not left behind silently, and it does not discard an answer that has already been obtained.
- **Consult hardening**: On macOS the shared host Seatbelt supplies the read/write wall; only after the outer layer is verified does the inner `--sandbox` change to `disabled` (cursor-agent's cursorsandbox is a second `sandbox_apply`, rc=71). argv is still assembled as `-p --mode ask --output-format json --trust --sandbox enabled --workspace <empty directory>`, and it is changed only after the fence wraps it. The executable is `realpath`'d so the home-directory symlink `~/.local/bin/cursor-agent` is not blocked by the read wall. `--force` / `--yolo` / `--approve-mcps` are not passed; `files=` is LOUD-rejected. Non-Darwin has only the vendor `--sandbox enabled` baseline and cannot claim a host read wall on that basis. If `OMNI_LLM_CURSOR_CONFIG_DIR` points at `~/.cursor`, global MCP comes back; do not add omni-llm itself under that usage.
- **usage**: The `result` of `--output-format json` is the reply; token fields are currently all `null`, `source: unavailable`.
- **agent / job lane**: Wired up, and it goes through the kernel Seatbelt fence (`seatbelt-fs`, same as claude/pi). On Darwin, after the outer layer is verified, the inner `--sandbox` is changed to `disabled`; non-Darwin relies on the vendor `--sandbox enabled`. The sync lane sends one shot of `-p --trust --sandbox enabled --workspace <workdir> --model <slug> --output-format json` (changed to `disabled` after the fence wraps it). Read-only adds `--mode plan` (not consult's `--mode ask`). The job lane switches to `--output-format stream-json` and pins `CURSOR_CONFIG_DIR` at `<job_dir>/cursor-config` (so `--resume` can find the same chat). cursor-agent has no `--session-id`; `session_id` is captured by the supervisor from the stream's `system`/`init` event (the same kind of capture as codex's `thread.started`, see `providers/job_runner.py`); resume uses `--resume <chatId>`. The `model` in the success envelope is the slug after effort folding (same as consult). The reply takes the JSON `result` field (sync lane) or the last assistant message in the stream (job lane, reusing the grok/claude normalizer; cursor's stream-json shape matches claude). Write mode passes `--force` (headless has nobody to approve Shell; the fence is the wall); `--yolo` / `--approve-mcps` / `--worktree` are still not passed. Read-only `--mode plan` does not pass `--force`.
- **Fable data retention**: The Cursor Dashboard may need Fable's retention policy turned on first, otherwise a live call fails (that is authentication/policy, not a routing error).
- **The fallback chain works as usual**: example `"cursor/sol,grok-4.6"`.
- **⚠️ A running MCP server must be restarted before it picks up the new backend**: same as the Grok section.

### MCP protocol: dual-era (2026-07-28 + 2025-06-18)

`2026-07-28` removed the `initialize`/`initialized` handshake — there is no negotiation. Each request carries its own protocol version and capabilities in `_meta`, and the server accepts or rejects requests one by one. This server **serves both eras at once**, judged by "how the client opens":

- The request's `_meta` carries `io.modelcontextprotocol/protocolVersion` or `clientCapabilities` → modern path, stateless handling.
- Sending `initialize` → legacy path (`2025-06-18`). A request without `_meta` stays on the old path (`_meta` that only holds something like `progressToken` is still legacy — the criterion is "carries a modern protocol field", not "has `_meta`").

Errors on the modern path: a missing required field or a wrong type → `-32602`; an unsupported version → `-32022`, with the versions we support attached in `data.supported`. `server/discover` (the spec requires an implementation, and it is also the era probe for stdio) returns DiscoverResult directly when it has no `_meta`, and is validated only when it carries a modern marker. `tools/list` and `server/discover` attach `ttlMs` / `cacheScope` cache hints (the spec allows them only on list/discover, **not on `tools/call`**); every result carries `resultType`, `tools/call` also attaches `structuredContent`, and every tool declares `outputSchema`.

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}' \
  | python3 server.py
```

## Model-catalog maintenance

`omni models` keeps the existing agy live list. To see each vendor's list source and update status, use `omni models status --json`; to list model IDs in the local cache, add `--details`. Refresh the local cache with `omni models refresh --provider all --profile default`, and compare differences with `omni models check --provider cursor --profile default`. For manual import, snapshot upgrades, profile isolation, and schedule examples, see [Model catalog maintenance](model-catalogs.md).

The explicit `agy-opus-<version>@<effort>` shorthand resolves only against the bundled AGY catalog. For example, `agy-opus-5.5@med` selects that exact Opus version's unique medium entry; `med` means `medium` only for this shorthand. Resolution happens before seats, health keys, and admission use the model name. An unknown version, missing effort variant, ambiguous match, or simultaneous `@effort` and `--effort` is a loud refusal, including inside a fallback chain. It never selects another version or provider. Existing canonical `agy/<id>` names remain unchanged. This names a normal consult transport; it does not establish tool-free review capability or add AGY to the agent/job lane.

Catalog status uses `source` for producer provenance and `origin=local|bundled` for storage location; adapter support does not establish account availability.
